## 一、先回答三个问题（结论速览）

**1）市面上做图像/视频清晰化的模型有哪些？**
按「能力」分五类，按「供给形态」分四路：

| 能力 | 说明 | 代表方案 |
| --- | --- | --- |
| 超分放大（Upscale） | 480p→720p/1080p，2~4 倍 | Topaz Proteus/Starlight、腾讯云 MPS 超分、阿里云 IMS 视频超分、Real-ESRGAN、SeedVR2 |
| 去噪/去压缩伪影 | 消除块效应、蚊噪、糊边 | Topaz Denoise/Nyx、腾讯云 MPS 综合增强、ffmpeg hqdn3d/nlmeans |
| 补帧/升帧率（Frame Interpolation） | 24/30fps→60fps，或慢动作 | Topaz Apollo/Chronos/Aion、腾讯云 MPS 插帧、RIFE、FILM、GMFSS |
| 老片修复/稳定/上色 | 抖动、划痕、黑白上色 | Topaz Video Utilities、腾讯云 MPS 老片修复、阿里云 IMS |
| 动漫专用超分 | 线条/色块不生成幻觉 | Topaz Gaia 2 (Animation)（比同族便宜约 50%）、AnimeSR、Anime4K（实时着色器） |

供给形态四路：**① 桌面商业软件**（Topaz Video、VideoProc、万兴、SVFI/Flowframes）；**② 云厂商 API**（腾讯云 MPS、阿里云 IMS/VOD 与视觉智能、火山引擎/BytePlus、百度、华为）；**③ 海外托管 API/聚合平台**（Topaz 官方 API、fal.ai、Replicate、Freepik/Magnific、WaveSpeedAI）；**④ 开源自建**（Real-ESRGAN/Real-CUGAN + RIFE，GPU 自部署）。

其中对本项目最"对口"的一条：**腾讯云 MPS 的增强模板带 `EnhanceSceneType` 场景预设，含 `ai_comic`（AI 漫剧）、`short_play`（短剧）、`LQ_material`（低清素材）、`AIGC`**，并**预置了「漫剧场景-大模型增强」模板 `327004`(1080P)** —— 比通用超分更可能"懂漫剧画面"，且**免工单、有质检闭环**；**单价最低的是火山引擎（¥3.0/分钟，资源包 4.5 折后 ≈¥1.35）与百度 MCP（¥2.4，但有准入约束）**。

**2）Topaz Labs 这些能接吗？**
**能，而且官方就有 REST API**（不是只能买桌面软件）：`https://api.topazlabs.com`，覆盖图片超分/去噪/锐化与**视频超分 + 视频补帧**。
官方文档明确写：*"With the Topaz Labs API, you get access to image upscaling, image denoise, image sharpen, video upscaling, and video frame interpolation."*
来源：<https://www.topazlabs.com/api>（页面实时抓取 2026-10-04）、文档站 <https://developer.topazlabs.com/>
实测：本机（中国大陆网络）直连 `POST https://api.topazlabs.com/video/express` 约 0.7s 返回 `401 UNAUTHORIZED`，端点在线可达。

**3）接入后能不能对 480p 视频做优化/补帧？**
能，且官方文档给出的正是这个用法：把 `output.resolution` 设为 1920×1080、`filters` 里挂超分模型（如 `prob-4`=Proteus）即完成 854×480 → 1920×1080（2.25×）；补帧用 `filters` 里的插帧模型（`apo-8`=Apollo、`chr-2`=Chronos、`aion-1`=Aion、`apf-2`=Apollo Fast、`chf-3`=Chronos Fast），参数 `fps`（15–240）、`slowmo`（1–16）、`duplicate`（去重复帧）。
来源：<https://developer.topazlabs.com/reference/video/create-express-request/create-express-video-request.md>

> ⚠️ 但「能不能接」≠「该不该这么用」。对本项目（漫剧/短剧，成片多为 5~30 分钟）真正决定成败的是
> **成本倒挂、耗时（可能比生成本身还慢）、人脸/文字崩坏、以及跨境数据合规**——见第四、五、六章。
> 一句话预判：**主力走国内云 API——腾讯云 MPS（¥3.36~3.96/分钟、人民币可开票、免工单、素材不出境、带漫剧预置模板），并行接火山引擎（¥3.0、资源包 4.5 折后 ≈¥1.35）做降本；
> Topaz 官方 API ≈¥8.8~13.2/分钟可作精品档但需先拿商用书面许可；含人脸的成片不得送境外；规模化后自建可压到 ¥0.1~0.2/分钟。**

## 二、需求拆解：所谓「清晰化」其实是四件事

用户诉求「对 480p 视频优化 + 补帧」，落到工程上是四条独立能力，成本与风险完全不同，**必须拆开定价与开关**：

1. **超分（Spatial Upscale）**：480p→1080p。AI 生成片本身没有噪点，主要是细节缺失 + 平台转码压缩伪影，所以：
   - 「精度型」（Proteus、Real-ESRGAN）——保留原貌、只做去伪影+锐化，风险低；
   - 「生成型」（Starlight、SeedVR2、AuraSR 类）——会**幻觉补细节**，人脸、字幕、手指易崩；对「已经好看但不够清晰」的成片，收益与风险都很高。
2. **补帧（Temporal Interpolation）**：30fps→60fps 让运动更顺，或做慢动作（`slowmo`）。动漫内容要选动漫调优模型（GMFSS/Anime，Topaz 用 Apollo/Chronos），否则线条会「果冻化」。
3. **修复类**（去噪/去压缩伪影/稳定/上色）：漫剧成片多数用不上，属于「素材修复」场景。
4. **重新生成 vs 后处理**（最容易被忽略的一条）：与其 480p 生成后再超分，不如**直接生成 720p/1080p**——质量真实、没有幻觉、没有额外等待，唯一代价是上游单价更高。
   **决策公式**（价格由运营在后台「价格管理」配置，项目里的单价都在 `model_prices` 表，非代码常量）：
   `p480(积分/秒) + p_enh(清晰化积分/秒) < p1080(积分/秒)` 且画质可接受 ⇒ 才值得做「480p + 后处理」。
   这条必须先算账，否则极易出现「用户花了更多积分、等了更久、画质反而更差」。

## 三、Topaz Labs 专项：事实核实结果（全部实测/实抓）

### 3.1 产品与能力
- 桌面：Topaz Video / Photo / Gigapixel；网页版 Topaz for Web（Video/Image）；移动端。来源：<https://www.topazlabs.com/api>
- 视频模型族（官方文档）：Proteus（精度超分）、Starlight（生成式超分，可将 AI 生成片与档案片超分到 4K）、Astra（创意超分）、Denoise（去噪/Nyx）、Frame Interpolation（补帧）、Video Utilities（去抖/去模糊/上色/前景移除）。
- 关键型号（`filters[].model` 代码，取自官方 OpenAPI schema）：
  - 超分：`prob-4`(Proteus)、`pnat-1`(Proteus Natural)、`rhea-1`、`thd-3/thf-4/thm-2`(Theia)、`aaa-9/aaa-10/ahq-12/alq-13/…`(Artemis)、`ddv-3/dtd-4/dtv-4/…`(Dione)、`gcg-5/ghq-5`(Gaia，含 Gaia 2 Animation)、`iris-2/iris-3`、`nxf-1/nxl-1/nyx-3`(Nyx)、`hyp-1`(Hyperion HDR)、`stab-1`(防抖)
  - 官方注明：**新模型可能先于文档可用**，权威清单以 `GET /video/status` 返回为准；Starlight/Astra 的代码未列在该 enum 中（属于此情况）。
  - 补帧：`apo-8`(Apollo)、`apf-2`(Apollo Fast)、`chr-2`(Chronos)、`chf-3`(Chronos Fast)、`aion-1`(Aion)

### 3.2 接口形态（可直接照抄实现）
最小可用请求（我已实测：无 key → `401 UNAUTHORIZED`；schema 校验先于鉴权）：

```http
POST https://api.topazlabs.com/video/express
X-API-Key: <key>
Content-Type: application/json

{
  "source":  { "container": "mp4" },
  "filters": [ { "model": "prob-4" } ],
  "output":  { "resolution": {"width":1920,"height":1080}, "frameRate":30, "audioTransfer":"None" }
}
```
- 返回 `requestId` + `uploadUrls`（预签名 PUT 地址，直接 PUT 上传源视频），随后 `GET /video/{requestId}/status` 轮询；完成时返回下载链接。
- 带源元数据的完整版：`POST /video/` + `PATCH /video/{id}/accept` + `complete-upload`（多分片，>500MB 必需，最多 150 个分片 URL）。
- 免上传/免下载：`source.external` / `destination.external` 传 **S3 预签名 URL**，Topaz 直取直存（本项目存储是天翼云 ZOS，官方兼容 S3，`server/internal/storage/zos.go` 用 minio-go 对接，加一个 Presign 方法即可用）。
- 回调：`notifications.webhookUrl`（成功与失败都会 POST）。缺省值：`videoEncoder=H265/Main10`、`container=mp4`、`dynamicCompressionLevel=High`；`audioTransfer=Copy/Convert` 时必须给 `output.audioCodec`。
- 返回 **estimates：credits 成本区间 + 秒级耗时区间**（空队列假设），并且**按下限计费** → 适合「先预扣、后按实结算」。
- ⚠️ **`filters` 可以一次串多个（官方示例 `nyx-3`→`prob-4`→`apo-8` = 去噪→超分→补帧），但官方明确「不保证按数组顺序执行」** → 依赖顺序（如先超分后插帧）**必须用小样实测确认**，不能想当然。
- ⚠️ **第三方页面的营销文案与 Schema 不一致**：fal 的 Topaz 端点宣称 "8× / 120fps"，但 Schema 实测 `upscale_factor ≤ 4`、`target_fps ≤ 60`（120fps 只出现在 `interpolate/video`）⇒ **按 4× / 60fps 设计**。
- 限制：请求 JSON body ≤ 3000 字节；输入文件 <100GB；无公开的时长/帧数上限；无公开并发上限，过载返回 `429`（指数退避）；**处理超时**约 4 小时（GAN 模型）/ 17 小时（生成式模型），超时按失败处理并通常 24 小时内全额退还 credit。
- 输出分辨率上限随编码器：H.264 4096×4096、H.265/VP9 8192×8192、AV1 16384×8704、ProRes 16386×16386；分辨率向上取整到 4 的倍数；**不带超分模型时输出分辨率被强制等于源分辨率**，不带插帧模型时帧率被强制等于源帧率。

### 3.3 计价（官方页面，2026-10-04 实抓）
- credit 单价：Starter `$0.12` / Developer `$50/月（500 credits，$0.10/credit）` / Scale `$240/月（3000 credits，$0.08/credit）` / Enterprise 面谈（含 **on-premise 私有化部署**）。来源：<https://www.topazlabs.com/api>
- 视频族基准（官方按 10s@1080p30 估算）：Proteus 4、Starlight Fast 6 / Quality 12、Astra 40、Denoise Fast 2 / Quality 4、**Frame Interpolation Fast 1 / Quality 2**、Video Utilities 2 credits。
- **Proteus 超分真表**（元/分种无关，单位 credits）：1s→1，10s→2（1080p）/6（4K），1 分钟→**8（1080p）/4（720p）/31（4K）**，10 分钟→76（1080p）/302（4K）；Gaia 2 (Animation) 比同族便宜约 50%。
- **Starlight**（按帧/credit）：Precise 2.6 约 26 帧/credit@1080p、约 12 帧/credit@4K → 1080p30 约 1.15 credits/秒。
- **补帧**（按 **GP = 新生成的插值帧的 gigapixel**，官方原文："GP means gigapixels of newly generated frames. For a 30→60 fps conversion, count the 30 interpolated frames generated each second — not all 60 output frames."）：Aion 6、Apollo/Chronos 2、Apollo Fast/Chronos Fast 1 credits/GP。官方算例：1920×1080、30→60fps、1 分钟 → 新帧 1800 帧 = **3.73 GP** → Apollo ≈ **7.46 credits**、Apollo Fast ≈ **3.73 credits**。
- 换算示例（按 $0.08~0.10/credit、¥7.1/$）：
  - 480p→1080p 只超分（Proteus 1080p，1 分钟 8 credits）：**约 ¥4.5~5.7/分钟**（720p 4 credits ≈ ¥2.3~2.8）
  - 30→60fps 只补帧（Apollo 7.46 credits / Fast 3.73）：**约 ¥2.1~5.3/分钟**
  - **完整一单「480p→1080p + 30→60fps」≈ 15.5 credits ≈ ¥8.8~11/分钟**（Fast 档 ≈ ¥6.6~8.3）
  - 生成式超分（Starlight Precise 2.6，约 26 帧/credit@1080p）：**约 ¥49/分钟**（4K 约 ¥107/分钟）——**贵在生成式幻觉补细节，慎用**

### 3.4 桌面版路线：能自动化，但**不能拿来做服务端**（重要）
- **系统要求**：Topaz Video 桌面版**不支持 Linux、不支持虚拟机/幽灵机、不支持 eGPU**（官方原文见 <https://docs.topazlabs.com/topaz-video/system-requirements>）→ 想在 Linux 服务器上跑桌面版批处理这条路被官方条款堵死。
- **确实存在 CLI**：桌面版自带一个含 `tvai_up`（超分）与 `tvai_fi`（插帧）滤镜的 ffmpeg 构建，可在一条命令里串联超分+插帧，例如
  `ffmpeg -i in.avi -filter_complex "tvai_up=model=alq-13:scale=2,tvai_fi=model=chf-3:fps=30" out.mp4`
  但该文档页（`docs.topazlabs.com/topaz-video/command-line-interface`）**现已 404、导航中已移除**，且 Starlight Mini 官方明确不支持 CLI → 定性为「存在但非官方支持，随时可能失效」。
- **授权**：桌面版订阅是 **1 seat**（同一时间只能一台机器用），多机/商用需 Pro 授权（>1M 美元营收组织）→ **拿桌面版做 SaaS 二次分发在授权上不成立**。
- ⇒ **结论：服务端只能走官方 API（或国内云 API / 自建）**，桌面版只适合运营同学本地手工处理少量精品镜头。

### 3.5 关于「Topaz 有 5 分钟时长上限」的澄清（避免误传）
这句口语说法混了两个不同来源，都不是"官方 API 的时长上限"：
1. **fal.ai 托管版**的 Topaz 端点页写着 5 分钟上限 → 这是 **fal 侧**限制。
2. **Topaz 桌面版 Cloud Rendering** 对 **Starlight 家族**限制 **9,000 帧/任务**（页面上按 30fps 换算≈5 分钟；其他模型无帧数限制）→ 出处 <https://docs.topazlabs.com/topaz-video/cloud-rendering>。这是"帧数上限 + 只限 Starlight + 只限桌面云渲染"。
3. **Topaz 官方 API 未公布任何时长/帧数上限**（与本文 3.2 一致）。

### 3.6 顺带一件事：图像清晰化比视频便宜两个数量级，建议与视频一起上（甚至先上）
本项目图片节点已有 1K/2K/4K 档（`web/src/types/prompt.ts:34`）。图片超分的性价比远高于视频：

- Topaz 图片 API 按**输出百万像素**计费：Gigapixel（精度超分）**24 MP/credit**、Wonder（生成式）4 MP/credit、Bloom（创意）2 MP/credit、Sharpen（GAN 24 / 生成式 20 MP/credit）、Denoise 24 MP/credit；单模型档位（如 High Fidelity 3 = 2 MP/credit、High Fidelity 2 = 4 MP/credit）见官方 Individual Model Pricing。
- 换算：一张 4K 图（约 8.3 MP）用 Gigapixel 只需 **约 0.35 credit ≈ ¥0.2~0.3/张**；即便用生成式 Wonder 也只要约 2 credits ≈ ¥1.2~1.5/张。
- 意义：① 可以「1K 生成 + 超分到 4K」，把上游图片成本与出图时间降下来；② 复用同一套执行器/计费/对账（`BillingTypePerCall` 按次即可），实现代价远小于视频。
- 开源自建的图像超分同样成熟（Real-ESRGAN BSD-3 / Real-CUGAN MIT / waifu2x MIT 可商用；注意 **Anime4K 官方声明不适合 480p 等低分辨率**、**SUPIR 禁商用**），成本比云 API 低很多——详见 5.5。

### 3.7 授权与商用：**接之前必须先拿书面许可**（最容易被忽略的坑）
- 官方文档**没有**说明 API 许可是否允许把处理结果通过商业 SaaS 面向终端用户转售，也未定义署名/水印义务；仅把 API 描述为"用于集成到应用和自动化工作流"。官方对 SaaS 转售的态度是：**联系 `enterprise@topazlabs.com` 取得书面确认**。
- 支付：官方原文只支持 **Stripe 月付信用卡**（*"We currently support monthly credit card payment processing through Stripe."*），**是否支持人民币/发票未证实**。
- 桌面版授权是 **1 seat**，多机并发需 Pro；官网套餐小字写 *"Personal and commercial use for orgs under $1M USD annual revenue."* → 桌面版不能作为服务端方案（见 3.4）。
- 检索到的 `topazvideo.cn / topazphoto.cn / topazstudio.cn` 等「中文站」**未证实为官方授权渠道**（疑似镜像/联盟站），不得据此判断官方在华有代理。
- ⇒ **结论：Topaz 官方 API 作为「精品档/兜底档」技术可行，但产品化关键路径应走国内合规通道（见第五章）；真要上 Topaz，先拿书面许可。**

### 3.8 官方对「480p → 1080p 的 GenAI 动漫短剧」的推荐（正好对上本项目场景）
- **480p 输入支持，但逐模型而异**：Starlight HQ 明确支持 480p–4K 输入，Starlight Mini 面向 SD/退化素材（可自动去隔行）；没有通用的「最低输入分辨率」门槛。
- 官方给出的选择顺序：① **Starlight Precise 2.6**（面向 GenAI 视频，时序一致性优先）→ ② 需保风格时用 **Gaia 2 (Animation)**（同族便宜约 50%）→ ③ **Proteus** 作为低中质量/压缩素材的**精确型**兜底。
- 工程含义：**漫剧（动漫风）优先试 Gaia 2 / Proteus 这两条"不造幻觉"的路**，Starlight 只在追求"更真实细节"的精品镜头用——它会重写细节，人脸/字幕/文字有崩坏风险（且贵约 10 倍）。
> 本章小结：Topaz 官方 API 已实证「可接、便宜、大陆可直连」，但**商用授权必须书面确认**；桌面版不可用于服务端。
> 渠道对比、合规红线、自建成本见第五章；工程落地见第四章。

## 四、libtv 接入方案（按现有架构落地，含改动清单）

> 依据代码事实：节点类型在 `server/internal/engine/executor.go:2770` 的 `NewDefaultRegistry` 注册；
> 模型清单在 `server/configs/models.yaml`（按渠道 wasu/dianxin 分 section，用 `usage` 过滤到节点）；
> 价格在 `model_prices` 表、由 `server/internal/billing/pricing.go` 的 `priceNodeDefs` 定义页签与计费类型；
> 异步上游任务用 `llm.AsyncTaskRef` + Redis 落盘续跑，对账用 `provider_tasks`（身份是 charge_key）。

### 方案 A（推荐，最小改动）：挂在「视频节点」的生成后处理上
用户诉求是「对成片做清晰化」，最自然的入口是视频节点上一个「生成后清晰化」开关，而不是新画布节点。

改动点：
1. `server/configs/config.yaml` → `ai.providers` 增加 `topaz`（APIKey/BaseURL）；`server/configs/models.yaml` 在两个渠道下各加 `enhance` 模型条目（或复用 `video` 组、用 `usage: [enhance]` 过滤），字段：`id/name/provider/model_id(=模型代码如 prob-4)/usage/description`，并扩展 `resolutions: ["720p","1080p"]`。
2. `server/internal/llm/enhance.go`（新）：完全照抄 `video.go` 的异步范式——`CreateTask`（POST /video/express → 拿 requestId + uploadUrls）→ `Upload`（PUT 源视频，可从自有存储取流，或改用 `source.external` 预签名直取）→ `PollStatus`（复用 `VideoPollConfig` 的间隔/预算，建议 interval 10s、timeout 25 分钟）→ 下载产物。
3. `server/internal/engine/executor.go`：`Register("enhance", NewEnhanceExecutor(...))`。执行器继承 `VideoExecutor` 的整套收尾逻辑（转存失败重试、`provider_tasks` 登记、失败退费规则、`detachedCtx` 记账）——**这套逻辑是现成的，新执行器必须复用而不是重写**。
4. `server/internal/billing/pricing.go`：`priceNodeDefs` 增加
   `{NodeType:"enhance", NodeName:"清晰化/补帧", ModelGroup:"video", BillingType:BillingTypePerSecond, Usage:"enhance"}`
   → 后台「价格管理」会自动多出一个页签（`web/src/pages/admin/PricingManagement.tsx` 是按服务端节点列表渲染的，另需在 `NODE_ICONS` 补一个图标）。计费直接复用 `BillingService.ChargeVideoByDuration(...)`：按**输出秒数 × 倍率档**收费，新增 `resolution` 维度（720p/1080p/4K）。
5. 前端：`web/src/components/nodes/VideoNode.tsx`（或其参数面板）增加「清晰化档位」选择（关闭/720p/1080p）+「补帧」开关（目标 fps），`web/src/components/nodes/index.ts` 若做独立节点再注册 `nodeTypes`。

### 方案 B：独立「清晰化节点」（后续，可复用素材、可单独收费）
在上述基础上新增 `web/src/components/nodes/EnhanceNode.tsx` 并注册 `enhance` 节点类型；后端 `parser.go` 的节点类型注释与 `validator.go` 无需改（类型是字符串透传），`engine` 只认注册表。收益：用户可对任意视频（含上传素材、白模白片、历史成片）做增强，便于单独定价与单独退费。

### 必须一起处理的四个工程问题（否则线上必炸）
1. **执行超时**：`handler.executionTimeout = 30 分钟`（`server/internal/handler/workflow_handler.go:281`），而清晰化的上游耗时可能远超生成本身（Topaz 官方给的失败预算是 4~17 小时）。对策：**按片段切分**（如每 10~30s 一段、并发 N 段、ffmpeg 拼接），把单段控制在几分钟内；或把清晰化走**独立队列 + 独立超时预算**，不要挤在生成任务同一个 30 分钟时钟里。
2. **并发闸门**：`queue.workers=10` 是全局生成并发上限，清晰化任务若混进同一个流会把生成挤掉。对策：新增独立 stream/消费者组，或在执行器里加独立信号量。
3. **对账与退费一致性**：清晰化同样要写 `provider_tasks`（`charge_key` 为行身份、`task_id` 存 Topaz requestId），失败退费规则沿用「上游明确拒绝才自动退」的判定，避免白付上游。Topaz 的 estimates「按下限计费」便于预扣→结算。
4. **幂等与续跑**：把 requestId 在拿到的那一刻落 Redis（`llm.AsyncTaskRef`），进程重启后接着轮询而不是重新下发——否则用户被扣两次费、上游跑两遍。

### 存储与出网
- 上传：Topaz 用 S3 预签名（本机 PUT）。当前 `Storage` 接口（`server/internal/storage/storage.go`）没有 Presign 方法，两条路：① 直接 PUT 到 Topaz 的 `uploadUrls`（改动最小）；② 给 ZOS/MinIO 实现加 `PresignGet/PresignPut`，用 `source.external`/`destination.external` 免上传免下载——**1 分钟 1080p 成片约几十 MB 到几百 MB，直传能省一整轮带宽与失败面**。
- **国内云厂商的"直取直存"实测口径（已核实）**：**直取可以**——阿里云 `VideoURL`、腾讯云 `InputInfo.Type=URL`、火山 `video_url`（支持 4 种协议）三家**输入侧都吃公网 URL**；**直存不行**——**输出必须落在各厂商自己的存储**（腾讯云是唯一文档提到「AWS-S3 源」的厂商，但注明**目前只支持转码任务**，增强任务是否适用需实测）。
  ⇒ 工程结论：清晰化结果**天然要多一次"厂商存储 → 自有存储"的搬运**，请把它算进 `executionTimeout` 预算，并在下载失败时保留可重试的远端 URL（注意**阿里云视频智能的结果 URL 只有 30 分钟有效期**，必须立即转存）。
- **执行耗时预算（排超时的关键输入）**：**火山是唯一给出官方 RTF 口径的厂商**——极速版 3~4×、标准版 6~10×、专业版 25/60× ⇒ **1 分钟 480p→1080p+60fps 约需 3~10 分钟**；其余厂商**均未公布**，只能实测。按此推算，**5~30 分钟成片若整段提交会直接撞上 30 分钟执行超时**（见"四个工程问题"），必须分段。
- 出网风险：即便网络可达（已实测），**素材出境**涉及 PIPL 合规与「生成合成内容标识」要求，**含人脸成片不得送境外**（见 5.3），境外 API 只宜做无人物素材的灰度与对标。

### 5.3 合规红线：**境外 API 不能承接含人脸的成片**（决定性约束，必须放在选型第一位）
依据（分线报告 04 §6，均抓取到官方法规/条款原文）：
- 《促进和规范数据跨境流动规定》（网信办令第 16 号，2024-03-22 施行）**第五条第(四)项**：只有「不满 10 万人个人信息（**不含敏感个人信息**）」才豁免；**敏感个人信息被明确排除**。**第八条**：向境外提供**不满 1 万人敏感个人信息**须**订立标准合同或通过认证**；**第七条第(二)项**：达 1 万人以上须**申报安全评估**。
- PIPL **第 28 条**：**人脸属生物识别 = 敏感个人信息**；第 38/39/55 条要求三条路径之一 + **单独同意** + 事前 PIA。
- 《人脸识别技术应用安全管理办法》（网信办、公安部令第 19 号，**2025-06-01 施行**）**第八条**：除法律另有规定或单独同意外，人脸信息应存储于设备内、**不得通过互联网对外传输**。
- **「去标识化」救不了**：PIPL 第 73 条(三) 去标识化后**仍是个人信息**；只有「匿名化」才脱离个保法——而超分/补帧的业务目的本身就是重建人脸细节，**与匿名化逻辑互斥**。
- 叠加现实：fal 的 DPA 只提供 GDPR/SCC/UK IDTA，**无任何 PIPL 对应机制**（连标准合同都缺对方可签的对等文本）；Topaz 官方 API 的商用授权本身也待确认（3.7）。

⇒ **漫剧/短剧成片几乎必然含人脸 ⇒ 哪怕一天只送 1 条，也可能需要标准合同备案或认证。结论：境外 API 只能用于「无人物/景物素材的效果验证与对标」，不得承接全量用户素材。**

**另一条容易被忽略的合规点（与走哪条通道、走哪个档位都无关）**：《互联网信息服务深度合成管理规定》第二十三条第（五）项**明确把「图像增强、图像修复等生成或者编辑图像、视频内容中非生物特征的技术」列为深度合成技术**——**超分/修复本身即被覆盖，不是"不开生成式档位就能避开"**；须同时做**显式标识（导出文件内）+ 隐式标识（元数据）**，并遵守 **GB 45438-2025**，该办法自 **2025-09-01** 施行。
⇒ 工程要求：**后处理链路必须保留（不得剥离）AI 生成标识的元数据**；另需留意 2026-07-15 已施行的《人工智能拟人化互动服务管理暂行办法》（是否触及由法务复核）。

### 5.4 网络现实：域名没被墙，但**大文件跨境传输会间歇性崩塌**（杭州联通 AS4837 实测）
- 可达性：fal.ai / api.fal.ai / queue.fal.run / v3.fal.media / replicate.com / api.replicate.com / topazlabs.com 均 200 或 401，**无被墙迹象**；Cloudflare anycast 把大陆流量送去 LAX（RTT ≈193ms）。
- **但**：下载 50MB 出现双峰（11.7 / 12.9 MB/s）后**掉到 13 KB/s 并超时**；10MB×6 轮中有 1 轮 0 字节超时 → **约 15–30% 的大文件跨境传输失败或严重劣化**；上传稳定但仅 **1.2 MB/s**（国内基线 17.6 MB/s）。
- 工程含义：「上传源视频 → 处理 → 下载成片」若两次跨境大文件传输，端到端成功率约 **50–85%**；1 分钟 1080p 成片（50–100MB）**光上传就要 40–80 秒**，与 GPU 处理时间同量级。
- ⇒ 若一定要用境外通道：必须分片续传 + 重试 + **自动回退国内通道**，且优先用「预签名直取直存」（少一次跨境往返）。

⇒ **自建（动漫档）比腾讯云 MPS 便宜 10~35 倍**（¥0.11~0.18 vs ¥3.36/分钟）；但 **SeedVR2 反向贵 5~11 倍**，只配做关键镜头。

> 官方仓库里 **Real-ESRGAN / SeedVR2 都没有吞吐数据**，唯一硬锚点是 RIFE README 的 "30+ FPS for 2× 720p on 2080Ti"。
> ⇒ **自建的第一步不是买卡，而是拿一条真实 480p 成片自测 RTF**；按悲观值算，自建相对 MPS 的优势会从 10~35 倍缩到约 2~3 倍，回本周期随之显著拉长。

- **RIFE 用 4.25，不要用最新的 4.26**：官方 README 原文 *"recommended to choose **4.25** by default for most scenes"*、*"the **anime scenes have been significantly improved**"*，且 *"**4.24+ is quite suitable for post-processing of some diffusion model generated videos**"* ← **直接命中 libtv 的 AI 生成素材**。
- **想要 4.25 必须走 CUDA/PyTorch**：`rife-ncnn-vulkan` 的模型表最高只到 `rife-v4.6`（落后约 1.5 年），`rife-anime` 仅对应上游 1.8，很旧。另注意其 CLI 语义：`-n` 是**目标帧数**不是倍率（目录模式默认 ×2）。
- **值得评估的候选（新方案，均已核实许可）**：**SAFA**（WACV2024，RIFE 作者团队，"Efficient **Space-Time** Video Super-Resolution"，把超分+插帧合成一段，理论上比两段式省算力并规避接缝/闪烁）；**VFIMamba**（NeurIPS 2024，`MCG-NJU/VFIMamba`，**Apache-2.0**，首个把 SSM/Mamba 用于插帧，官方称高分辨率 VFI 有潜力、支持 Nx 任意倍率，⚠️ **README 未提动漫**）；**MoMo**（AAAI 2025，`JHLew/MoMo`，**Apache-2.0**，有 MoMo-10M 轻量版）。
  ⇒ **建议：动漫仍以 RIFE 4.25 + GMFSS_Fortuna 为主**（这两者有明确的动漫验证记录），上述三个只作「小样本 A/B」候选。

**两条会直接影响效果的否定结论**
- **Anime4K 不适合 480p**（官方 README：optimized for *native 1080p* anime，*not* optimized for **480p**/**SD**，且 *not replacement for SRGANs*）→ **不要当 480p 修复主力**。
- **SeedVR2 官方自曝对 480p AIGC 会过锐化**（"…leading to **oversharpened results occasionally (especially on small resolutions, e.g., 480p)**"）——**正好命中 libtv 的 480p 生成片**；且其论文承认 VAE 占 720p×100 帧总耗时 **>95%**，优化 DiT 收益极小。
- **SeedVR2 的容量门槛**（不是速度）：`1×H100-80G` 上限 100×720×1280，**做 1080p 需 4×H100-80G（sp_size=4）**；8GB 显存可跑（GGUF Q4 + BlockSwap + VAE tiling），24GB+ 用 FP16。

### 5.5.1 工程细节（自建与云 API 都适用，踩了就翻车）
1. **顺序：先超分、后插帧**（SVFI 官方文档原文「SVFI 先超分后补帧」）。算力账：先 SR 只需 1800 次超分，先 VFI 要 3600 次，**贵一倍**。例外：用 GMFSS 等高显存插帧模型 OOM 时可改 VFI→SR。
2. **2D 动漫必须先「帧去重/抽帧」再插帧**，否则抖动/鬼影（Flowframes 官方：Frame De-Duplication *meant for 2D animation*）；**必须做转场检测**，否则每个剪切点产生融合鬼影。
3. **中间结果不要落盘成 8bit PNG/JPEG**（一次量化丢掉 10bit 全部收益，动漫大渐变最易出色带）；音频 `-c:a copy` 直通；`-framerate` 必须在 `-i` 之前；VFR 素材先转 CFR。
4. 长视频分块（SeedVR2 官方 CLI：`--chunk_size 330 --temporal_overlap 3 --10bit`；注意 **batch_size 必须 4n+1**）；分块接缝与**时序闪烁（temporal flicker）**是主要质量风险点。

### 5.6 上游聚合网关能不能上架超分模型？—— **短期不可行**（已验证后的裁定）
- 事实：现有两个聚合网关（华数 `token.wasu.cn`、电信 `ai.ctaigw.cn`）我实测过模型清单，**华数 74 个、电信 11 个，均无任何超分/增强/插帧模型**。
- 原因（比"没有"更重要）：**超分能力在国内主流大模型平台上普遍缺席**（阿里云百炼没有、火山方舟没有），因为这些网关的协议是「大模型按 token/次数计费」，而清晰化是**媒体处理类、按分钟计费、异步长任务**——网关需要**新增一类「媒体处理」路由维度与按分钟计费模型**，属于**协议扩展，而不是加一个 model id**。
- ⇒ **行动建议**：① **自建 provider 走国内云 API**（本报告的 P1 路径，不依赖渠道方）；② **并行请渠道方谈「媒体处理能力转售」**——成了就是零接入成本、零合规增量；**但不要把它当成近期可依赖的方案**。

## 六、决策建议（分阶段）

- **P0（已完成实现，零成本、零外部依赖）**：先接任何外部模型之前，先落地「引导 + 本机 ffmpeg 轻量档」。
  - **① 生成侧引导**：清晰度面板选中 480p 时出现引导条 —— 用**真实定价表**算出「直接出 720p 只多 N 积分」（`p480 + p_enh < p1080` 这条账），并给两个可点动作：`切到 720p`、`加清晰化节点`（一键建节点+连线）。取不到价格就不显示数字（不编数）。
  - **② 清晰化档（本机 ffmpeg）**：滤镜链 `deblock=strong → hqdn3d(轻) → cas(0.45)`，`hd` 档再加 `scale=…:flags=lanczos` 放大到短边 720；`libx264 -crf 20 -preset veryfast`；**音频编码兼容则直通、否则转 AAC**（webm/opus 直通进 mp4 会打不开）；`-map_metadata 0` **保留元数据**（合规：AI 标识等隐式信息不得在清晰化环节被剥离）。
  - **③ 独立节点（关键设计决定，不是挂在视频节点上的开关）**：`Register("enhance", …)`，从上游连线取视频 —— 于是**能对已有素材重做**（不必重新生成=不重复扣费）、可反复 A/B、**独立超时与并发闸门**，并且**它就是 P1 云端档的落点**（换 provider 即可，接线不用再动）。清晰化节点上带**渠道（provider）选择**：`provider` 字段写进节点数据，后端按注册表解析，
本机 FFmpeg 是今天唯一已开通的渠道（`GET /api/enhance/providers` 把清单交给前端，
前端不硬编码渠道文案）。P1 接云端档时 = 后端加一个实现文件 + 注册，前端自动多一个选项、不用发版。

上游取值顺序：显式 `sourceNodeId` → 本次执行刚产出的 `videoUrl` → 节点 data 里已存的 `videoUrl`（老片重做路径；`engine.BuildNodePlan` 保留全图 connections 与 nodes.data，所以单节点执行也能读到上游片）。
  - **④ 护栏**（审代码时发现的四处风险，已实现并实测）：**时长闸门**（源片 >120s 明确拒绝并提示走云端档，而不是跑到超时）、**并发闸门**（同时最多 2 个 ffmpeg 进程；队列有 10 个 worker，不限制会把 CPU 打满连累生成）、**旋转感知**（手机竖拍片的宽高是存储尺寸，带 90/270 显示矩阵时必须按显示尺寸算目标，并显式清掉 `rotate` 标签，否则播放器会二次旋转）、**失败语义**（节点内失败=真失败，不允许"回退原片"造成假成功）。
  - **本机实测（Intel Mac，纯 CPU，4s 片段）**：`clean` **1.42s（≈0.35×RTF）**；`hd` 480p→720p **3.57s（≈0.89×RTF）**，854×480→1282×720，竖屏 480×854→720×1282 尺寸正确；短边 720 目标下远快于早前测的 1080p 档（12.4s）；**minterpolate 补帧 30→60fps 处理 4s 耗时 90.4s（≈22.6×RTF）→ CPU 补帧依然不可行，补帧必须走 API/GPU**。
  - 代码：`server/internal/service/enhance_lite.go`（能力层）、`server/internal/engine/enhance_executor.go`（节点执行器）、`web/src/components/nodes/EnhanceNode.tsx`（节点 UI）、`web/src/utils/enhanceNode.ts`（一键建节点）；**P0 不扣积分**（本机处理、无外部成本）。
- **P1（3~5 天）**：接入**腾讯云 MPS** 作为主力（≈¥3.4~4.0/分钟、人民币、可开票、不出境、**免工单、带 `ai_comic` 漫剧预置模板 `327004`、有媒体质检可做自动验收**），落地「清晰化档位」开关 + 按输出秒数计费 + 独立队列/超时预算（**火山公布的 RTF 告诉我们 1 分钟成片要 3~10 分钟，整段提交必撞 30 分钟超时 → 必须分段**）。先用 20~30 条真实 480p 成片做 A/B（**MPS 超分 vs 直接生成 720p vs 原生 1080p**），用媒体质检/PSNR/SSIM/VMAF 打分定档与定预设。
- **P1.5（降本通道，接入成本几乎为零）**：同一天把**火山引擎 VOD/AI MediaKit** 也接上（`Action=StartExecution`、`Modules[].Type=SR/VFI`、`Target.Fps` 高于原片即自动插帧），**¥3.0/分钟、买资源包 4.5 折后 ≈¥1.35/分钟**（**比 MPS 更低**），用**同一套 provider 抽象**做成可切换通道 → 直接拿"两个通道谁更好更便宜"的实测数据决定主次（注意：**必须小额实测出账**，因为另一路调研给出 ¥10.7 的冲突口径）。百度 MCP 虽 ¥2.4 最低，但有**白名单+仅北京+必须入 BOS** 三重约束，**先谈不先接**。
- **P2（按需）**：Topaz 官方 API 作为**精品档/兜底**——关键是**拆分定价**：Proteus 超分（¥4.5~5.7/分钟）与 Apollo 补帧（¥4.2~6.4/分钟）都不贵，**贵的是生成式/创意档**（Starlight ≈¥49/分钟@1080p30、¥98/分钟@1080p60——它按**输出帧数**计费，约 26 帧/credit；Astra、SDR→HDR 更贵），所以精品档只开「精确型超分 + 补帧」，别默认开生成式。**上 Topaz 之前先拿 `enterprise@topazlabs.com` 的书面商用确认**（见 3.7），未拿到前不要放进产品关键路径。
- **P2.5**：用 fal 的 `fal-ai/bytedance-upscaler/upscale/video`（≈¥6.1/分钟、含 60fps、有 `short_series` 短剧预设）做**效果对标**——但注意 5.3 的合规红线：**只能用无人物/景物素材做验证，不得承接用户成片**。目的是判断「短剧/AIGC 预设」是否比国内通用超分更懂漫剧画面，进而决定是否向国内云厂商要同类预设或走自建。
- **P3（规模化后）**：自建 GPU 微服务（**动漫档 Real-CUGAN 2x + RIFE 4.25 或 GMFSS_Fortuna(均 MIT)，租 4090 ≈ ¥0.11~0.18/分钟；若 RTF 悲观则 ≈¥1.2~2.0/分钟**）。**触发门槛**：先自测 RTF，且月处理量达**数十小时**成片时再上；月量 <300~500 分钟直接买 API 更省事。**注意**：不要用 Anime4K 修 480p、SeedVR2 对 480p AIGC 会过锐化且贵 5~11 倍；Real-ESRGAN **商用必须关闭 `--face_enhance`**（GFPGAN 非商用）；中间结果别落 8bit PNG；2D 动漫**必须先抽帧去重 + 转场检测**再插帧。其余许可红线见 5.5（SUPIR、CodeFormer 禁商用、Video2X AGPL）。

### 6.0 一句话总结
**能不能接：能。怎么接：主力用国内云 API（腾讯云 MPS，¥3.36~3.96/分钟、可开票、不出境、免工单、带漫剧预置模板 `327004`），并行接火山引擎（¥3.0/分钟、资源包 4.5 折后 ≈¥1.35）做降本通道，在视频节点后面挂一个「清晰化/补帧」档位与独立计费；Topaz 官方 API 作为精品档（¥8.8~13.2/分钟，需先拿商用书面许可）；含人脸成片不得送境外；规模化后再上自建 GPU（可降到 ¥0.1~0.2/分钟）。**

### 6.1 定价与毛利建议（可直接拿到后台价格管理配置）
成本量级（1 分钟 1080p）：**纯超分 720p** ≈ ¥0.33（腾讯云）/ ¥2.3~3.4（Topaz）；**纯超分 1080p** ≈ ¥0.66（腾讯云）/ ¥4.5~6.8（Topaz）；**加补帧到 60fps** ≈ ¥3.36（腾讯云）/ ¥8.8~13.2（Topaz）。
⇒ **MVP 先只做「超分 + 去噪」（成本可忽略，用户感知最直接），把「补帧」做成单独勾选/单独收费的增值项**。否则一刀切开启会让分钟成本从 ¥0.33 推到 ¥3+，把生成环节的毛利吃掉。
⇒ 后台落地：`model_prices` 按 `node_type=enhance` + `resolution(720p/1080p/4K)` 分别配单价（`per_second`），并预留「是否补帧」这一档的加价。

### 6.2 尚未证实/待办（不许当作定论）
