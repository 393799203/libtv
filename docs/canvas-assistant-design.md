# 画布创作助手：在现有蛙导上扩展创作编排

## 目标

让用户用对话推进当前项目：知道接下来该做什么，也能直接创建、修改、连接节点并发起生成。
助手位于画布右侧，可随时收起；现有节点编辑和生成入口继续可用。
以最新主分支 `ae83608` 的蛙导为基础，助手只在具体创作画布中显示；
首页和项目列表不显示助手，避免在没有画布上下文时承诺创建节点。
沿用免费对话与平台 token 成本日志策略，不改变原有节点计费。

## 第一版范围

1. 读取当前未保存的画布摘要、选中节点、分镜和素材准备状态。
2. 对话解释当前进度，给出可点击的下一步建议。
3. 根据明确指令创建文本、分镜、图片、视频、音频节点，填写提示词和建立引用。
4. 修改已有节点的名称和提示词；不允许删除节点、清空画布、改写媒体产物。
5. 创建、修改、连线作为一个画布事务，一次撤销。
6. 明确要求生成时，展示生成目标、模型和预估积分，点击任务卡上的“开始生成”提交。
7. 复用现有保存、单节点执行、SSE 和生成恢复机制，在对话任务卡中显示真实节点状态。
8. 按用户和项目保存本机最近的对话；清空对话不影响画布。

## 交互

- 桌面端进入创作即显示右侧辅助面板；仅在顶栏保留“蛙导 · 创作助手”入口，
  用图标、浅青背景与展开状态区分，收起后从同一入口重开，画布内不重复放按钮。
  窄屏将顶栏工具排为两行，保持入口和保存等工具均可访问。
- 创作建议随选中节点的故事、分镜、图片、运行和失败状态更新；只有点击建议才发起模型请求。
- 初始展示“我下一步该做什么”“根据选中内容创建下游节点”等示例。
- 输入框上方显示本轮引用的选中节点；发送时捕获画布快照，避免等待过程中选择变化。
- 纯咨询返回建议，不修改画布。明确的创建、修改指令自动执行经过校验的画布操作。
- 助手回复与执行结果分别展示，不能把“准备执行”说成“已生成成功”。
- 回复和生成卡片中的节点以名称展示，点击后选中并定位；同名节点加序号，
  已删除引用显示失效状态。旧回复中的已知内部 ID 也转换成可定位名称。
- 画布在请求期间发生内容或连接变化时，保留建议并要求重新规划，不执行旧计划。
- 节点移动、缩放、选中变化、生成进度文案变化不使计划失效。
- 关闭面板保留对话；项目切换取消尚未完成的对话请求，不向另一个项目落节点。

## 实现结构

前端捕获画布摘要 → `POST /api/projects/:id/assistant/chat` →
当前渠道的文本模型返回结构化计划 → 服务端校验工具白名单与节点引用 →
前端再次校验最新画布 → 单次画布事务 → 自动保存 →
用户点击生成任务卡 → 现有单节点生成接口 → SSE 回写节点与任务状态。

模型返回 JSON 工具计划，不执行模型输出的 JavaScript、Shell 或其他任意代码。
这种方式可复用现有兼容协议的文本模型，不要求每个供应商实现相同的原生工具调用协议。

### 计划协议

- `message`：解释判断或将要进行的操作。
- `nextSteps`：最多三个后续指令，作为快捷按钮。
- `createNodes`：新节点，使用 `new:` 开头的临时引用；真实 ID 由节点工厂创建。
- `updateNodes`：只修改已存在节点的 `label`、`prompt`。
- `connections`：已有节点 ID 或新节点临时引用之间的数据流连接。
- `generateNodeIds`：本阶段建议生成的节点，最多八个。

新节点可携带 `scriptNodeId`、`shotId`、`refIndex`，用于分镜图片归属；
连接的上游同时转换成提示词引用，沿用现有 `mentions` 机制。
模型、渠道、默认参数由应用根据可用模型配置填充，不接受模型自行发明的模型 ID。

### 上下文与一致性

只发送节点的创作字段、资产引用、分镜摘要和“是否有产物”等状态，不发送媒体二进制或完整画布布局。
优先保留选中节点及其邻居，限制节点数、分镜数、文本长度和请求体大小，并明确提示截断。
服务端先检查项目归属，再调用模型；客户端摘要不作为项目访问权限的依据。
服务端和前端都校验节点类型、引用存在、重复引用、自环、环路、忙碌节点和数量上限。

### 生成与计费

- 沿用现有蛙导的免费对话策略，平台侧 token 用量写入现有 `assistant_logs`。
- 独立的生成任务使用现有节点计费，生成前列明数量和预估积分。
- 不把报价失败视为免费；未知价格明确显示“暂无法估算”。
- 对话防重复提交采用现有幂等存储；实际节点生成继续使用原有计费和失败结算。
- 模型计划格式或归属校验失败时，将具体错误反馈给模型自动纠正一次；
  网络/渠道失败不重试。两个计划都通过相同校验，只有最终有效计划返回前端执行。
- 普通节点不展示分镜归属字段；空的孤立槽位序号可忽略，已有分镜图片未填槽位时默认首帧，
  明确无效的分镜/镜头标识仍然拒绝。
- 画布摘要在前端限制为约 96 KB，服务端再限制摘要 128 KB、总请求 256 KB、
  历史 24000 字和模型输出 8192 token，约束免费对话的平台成本。
- 第一版仅执行当前已具备输入的阶段；未产出的依赖不会被自动跨阶段生成。
- 已有生成结果不会因为点击旧任务卡被意外再次生成：任务卡执行前检查目标及依赖是否变化。
- 生成任务签名只记录实际生成参数、目标已有产物及上游参考内容；递归规范对象键顺序、
  按节点ID排序，忽略名称、布局、编辑状态、进度、缩略图和自动探测尺寸等展示元数据。
  输入连线与参考图数组仍保留原顺序，避免首尾帧被交换。
- 旧版任务卡携带的完整快照会用相同规则比较，退出重进和 JSONB 字段重排不再使它失效；
  未知或损坏快照不自动放行，已有执行仍由运行状态和订阅检查拦截，恢复任务不会自动生成。
- 真实参数或素材变化时，任务卡改为显示可点击的“重新规划”按钮，围绕原任务仍存在的
  节点重新读取画布；不要求用户重输指令，也不自动提交生成，新计划仍需点击“开始生成”。

## 验收

1. 空画布问“下一步做什么”：返回可用建议，不添加节点。
2. 要求创建短片创作流程：节点、名称、提示词和连接实际落到画布，可一次撤销。
3. 选中已有分镜要求补首帧：建立有分镜归属的图片节点，保留素材引用。
4. 选中已有图片要求做成视频：建立引用原图的视频节点，可点击卡片发起生成。
5. 任务提交后显示真实进行中、成功和失败状态；关闭助手不影响已有生成。
6. 模型输出非法工具、伪造节点、构造环路、修改运行中节点均被拒绝。
7. 请求期间画布变更、切换项目、失败重试不会误修改别的画布或重复落节点。
8. 无模型、无权限、余额不足、网络失败有明确反馈。

## 后续阶段

服务端持久化会话与任务、跨阶段依赖调度、生成后主动评估、长期创作目标与风格记忆。
这些需要独立的任务生命周期，第一版不通过浏览器里长期等待来实现。

## 验证命令

- `cd server && go test ./...`
- `cd web && npm run test:assistant`（使用 Node 24 原生 TypeScript 支持）
- `cd web && npx tsc --noEmit -p tsconfig.app.json && npm run build`
- 浏览器回归：启动 Vite，配置 `PLAYWRIGHT_MODULE` 指向已安装的 Playwright，
  执行 `node tests/assistant-browser.mjs`。所有 API 均被拦截，不创建真实账号或扣费。

浏览器回归覆盖咨询不建节点、创建与引用、保存、生成提交与 SSE 结果、
面板收起重开、等待中撤销使旧计划失效，以及窄屏面板边界。
