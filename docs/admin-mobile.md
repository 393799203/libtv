# 运营后台移动端适配

手机端（宽度小于 768px）保持管理员权限要求，在头像菜单中提供“运营管理”入口。后台顶部使用带分组名称的原生模块选择框，切换业务、财务和商务模块；桌面侧栏保持原样。

- 用户、邀请与对账使用专门的紧凑列表，优先展示身份、关键指标与状态，完整字段和设置按需展开；套餐继续使用带字段名称的记录。手机端取消固定列和横向滚动，桌面端保留表格。
- 用户搜索、角色和渠道筛选独立换行，搜索没有结果时筛选栏仍然可用。手机端同时展示渠道、项目资产数、最后操作和积分。
- 版图、视频和风格卡片的操作无需悬停即可使用。手机视频列表单列、风格列表两列；平板相应降低列数。
- 充值、账单、素材编辑、套餐和邀请明细弹窗限制在可视屏幕内，表单可滚动。邀请明细在手机上使用全宽抽屉。
- 渠道与价格在手机上使用同一个纵向滚动区域，避免常驻渠道概览挤掉价格区。价格字段支持数字键盘。
- 用户角色和渠道配置放入“账户设置与详情”，充值与积分明细直接可用；最后操作时间始终展示。邀请页优先显示邀请人数、付费人数、充值和净消费；对账页优先显示状态、项目和扣退积分，任务号、用量及备注位于详情，高级筛选可展开。

## 验证

`cd web && npx tsc --noEmit -p tsconfig.app.json && npm run build`

`PLAYWRIGHT_MODULE=/path/to/playwright/index.mjs node tests/admin-mobile-browser.mjs`

浏览器脚本使用模拟数据，在 320、390、768、1440 宽度及 844 × 390 横屏检查 8 个模块、主要弹窗、溢出、空搜索恢复、移动管理员入口和桌面布局。脚本不提交充值、审核、删除等修改。`QA_ORIGIN` 可指定静态预览或线上前端，API 仍由测试拦截。

证据来自 Chromium 手机视口与触摸能力模拟，未覆盖实体 iPhone / Android 的原生选择器和软键盘。权限回归沿用 `tests/admin-access-browser.mjs`，确保普通用户无法进入后台。
