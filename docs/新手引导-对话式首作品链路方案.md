## 0. 结论先行

1. **定位**：新手引导不是「教程」，而是一个**陪用户把第一条作品做完的对话式教练**。衡量它的唯一标准是「首作品完成率 / 完成时长」，不是「看完了多少步」。
2. **形态**：常驻的 AI 聊天气泡（可折叠），挂载在 `GlobalComponents`（`web/src/components/GlobalComponents.tsx`，目前只挂了 `LoginModal`），在工作台里展开成右侧对话栏。
3. **两阶段（已确认）**：阶段一**免费**陪用户把「故事 + 首帧图」做出来（平台承担约 41 积分）；**付费点精确卡在「图 → 视频」这一步**，用新手礼包解锁；阶段二完成首作品并解锁分镜流水线、漫剧 previz、增强补帧等重功能。**两个阶段是同一段对话，不是两个引导**——充值只是对话里的一步。
4. **⚠️ 最大风险不是技术，是积分**：线上**注册不送任何积分**，`Billing` 中间件（`server/internal/middleware/billing.go`）在余额不足时直接返回 `402 / code 4002`。原设想「阶段一就做出完整视频」**必然断在第一次生成**；因此付费点必须后移，但阶段一**不能零产出**（见 §2.3、§2.4）。
5. **架构选型**：**编排器放前端**，后端只负责「内容生成 + 话术」。画布状态就在前端 `canvasStore` 里，且已暴露 `addNode / connectNodes / updateNodeData / startNodeExecutions` 一整套能力，引导可以直接操作真实画布，而不是做个假 demo。
6. **复用优先**：`GenerateStory`、`GenerateScript`、提示词生成、SSE 执行推送、积分扣退、失败退费**都已经有了**，引导层主要是「编排 + 对话壳 + 进度持久化」。前端也已有 `tech-*` 样式体系与 `EmptyState` 可复用，但**没有消息气泡/打字机组件**，这部分要新写。

## 1. 现状盘点

### 1.1 新用户当前旅程（以及断在哪）

| 步骤 | 现状 | 问题 |
|---|---|---|
| 注册 | 邮箱注册即用，**0 积分** | 无法生成任何东西（`402`） |
| 落地页 | `/` = `VideoListPage`（公开作品流） | 是「看别人的」，不是「我要做」 |
| 找入口 | 导航 → 我的项目（`/projects`，空状态：「点击右上角『新建项目』开始创作」） | 入口不显眼 |
| 新建项目 | `MyProjectsPage.tsx:54-56` → `createProject({name:'未命名'})` → `navigate('/project/'+id)` | 项目名默认「未命名」，无题材引导 |
| 工作区 | **空画布，已有 4 张「场景链路卡」**：剧本创作 / 分镜出图 / 图生图 / 图生视频（`Canvas.tsx:69-100 EMPTY_GUIDE_SCENARIOS`，`applyScenario:865-905`） | 已经比纯空白好，但本质仍是**让用户在 4 条链路里做选择**，选完依然面对「提示词怎么写、模型怎么选、积分够不够」 |

## 2. 产品设计

### 2.1 设计原则

1. **对话即操作**。AI 说的每句话后面，画布上都要真的发生一件事。
2. **每步都有可见产出**。不允许「连着聊 3 轮屏幕上什么都没变」。
3. **用户随时可接管**。AI 不锁画布；用户手动改过的节点标记 `managedBy:'user'`，AI 只读不写。
4. **不制造假流程**。所有操作走真实 `canvasStore` + 真实执行引擎。
5. **可跳过 / 可回退 / 可重入**。关掉聊天框不丢进度。
6. **不替代现有入口**。那 4 张场景卡继续保留；对话引导是它的「上一层」，能直接调用 `applyScenario`。

### 2.2 形态与人设

- **入口**：右下角常驻气泡（首次登录自动展开一次，之后折叠为按钮）。**右下角是空闲区**：左侧边缘已被资产库把手占用（`WorkspacePage.tsx:358-374`），右侧是随节点锚定的 PromptPanel。
- **在工作台**：展开为右侧 360px 对话栏，不遮挡画布；AI 提到的节点 `spotlight` 高亮并平移视口。
- **人设**：「蛙导」。语气是**坐在旁边、手很快的搭档**——不说「请点击左上角的按钮」，而说「我先把画面生出来，你看看像不像你要的感觉」。
- **不做选择题**：题材/风格/时长都用自然语言或**可点的建议气泡**（点=发一句话），不用表单和下拉框。

### 2.3 阶段一：免费做到「故事 + 首帧图」（目标 ≤ 3 分钟、≤ 4 轮对话）

阶段一**不涉及付费**，由平台承担一次低成本生成，目的是让用户**手里留下东西**——这一点是本方案与「纯讲解式引导」的分水岭（见 §2.4）。

| 步 | AI 做什么 | 后台动作（真实调用） | 用户做什么 | 产出 | 积分 |
|---|---|---|---|---|---|
| **S0 开场** | 「想做什么样的片子？」+ 3 个可点示例 | `createProject` → `navigate('/project/:id')`；读 `/api/onboarding/state` | 说一句话 / 点示例 | 进入画布 | 0 |
| **S1 成稿** | 把一句话扩成 3~5 句小故事 | `createNode('text')` → `addNode` → `GenerateStory` | 看一眼，不满就说「再热血点」 | text 节点 + 故事 | 15 |
| **S2 出图** | 「我先把主角定格成一张图」 | `createNode('image')` + `connectNodes` + `startNodeExecutions`（`wan2.7-image`） | 可选：说风格 | image 节点 + **首帧图** | 26 |
| **S3 收口** | 「这张图就是你的第一个镜头了。要让它动起来吗？」 | 高亮该 image 节点，展示「图 → 视频」的结果预览 | 决定是否继续 | 作品雏形：故事 + 首帧图 | 0 |

**阶段一平台成本 ≈ 41 积分 ≈ 0.3~0.7 元/人**（按线上套餐汇率折算，见 §3.9）。

> 要点 1：**阶段一绝不能零产出**。原设想「阶段一直接做出完整视频」会撞上 0 积分；但如果改成「纯讲解」就走向另一个极端——用户聊完手里什么都没有，此时要求付费，转化率会非常难看。**留一张图在手里，是最低成本的「已投入」证明**。
>
> 要点 2：S2 必须用**便宜档**（`wan2.7-image` 26），分辨率/比例/风格全部由 AI 取默认值，不暴露参数——第一次就陷入参数选择是最大的劝退点。
>
> 要点 3：**把付费点卡在「图 → 视频」**，恰好落在用户价值感最高（静态变动态）、平台成本也最高（40~52 积分）的那一步，动机最强、最不牵强。

### 2.4 付费衔接点：新手礼包（整个漏斗的枢纽）

这一步是整个链路能否跑通的关键，五条设计要求：

1. **支付不跳出对话**。在聊天框内直接拉起 `PointsMallModal`（或专为首充做的精简版），**不要跳转到另一个页面**——「跳出」是这类漏斗最大的流失点。
2. **支付成功后自动推进**。监听 `credits_changed` 事件（`useExecutionStream.ts:378-385` 已把余额写回 `authStore`）或轮询支付结果（`PointsMallModal.tsx:145` 已有先例），到账后**在同一条对话里**直接说「到账了，我这就让它动起来」，接着走 S4。用户不应感觉到「引导结束了，又开始了另一个引导」。
3. **不充值也能挂起，不能死掉**。给「稍后再说」出口，引导状态存后端（`OnboardingProgress`），下次回来从这一步接着走。
4. **不重复骚扰**。被拒绝后设冷却期（如 24h）再提，且换话术，不要复读。
5. **首充礼包建议单独定价**。线上现有最低档是「试用包」50 元 / 3000 积分（badge「学生试用」，`points_packages` 表）。对一个刚聊了 3 分钟、还没看到成品的用户，**50 元门槛偏高**。建议做 **9.9~19.9 元的首充礼包（给 500~1000 积分）**，够完成首作品 + 若干次重试，制造「首充超值」感。

### 2.5 阶段二：充值后完成首作品 + 进阶能力

充值成功后**不换会话**，继续在同一个聊天框里走完：

| 步 | AI 做什么 | 后台动作 | 积分 |
|---|---|---|---|
| **S4 出片** | 「让这张图动起来，5 秒」 | `createNode('video')` + `connectNodes` + 执行（image2video 480p） | 40~52 |
| **S5 加料（可选）** | 「配句旁白？」 | `createNode('audio')` TTS | 26 |
| **S6 收尾** | 「成片好了，起个名字发布出去？」 | `AddShowDialog`（预填标题、预选分类，封面 `showApi.captureCover` 自动截帧）→ `POST /api/shows` | 0 |

**阶段二合计 ≈ 40~78 积分**；首作品总成本 81~119 积分。

> 发布时 **`category_id` 必填**（`AddShowDialog.tsx:426`），AI 必须预选，否则 S6 又变成让用户做选择题。
>
> **没有多镜头自动合成**：前端 ffmpeg 只用于截帧/片段重拍/图片处理（`frameCapture.ts`、`VideoSegmentBar.tsx`、`imageops/*`），不存在「多镜头拼接成片」的能力。所以**首作品 = 单个视频节点的产物**，正好和这条直线链路吻合；多镜头叙事留给下面的进阶模式。

完成首作品后进入**进阶模式**，以任务卡片形式按需解锁（不做线性教程）：

| 主题 | 触发 | 涉及能力 | 教学载体 |
|---|---|---|---|
| 多镜头叙事 | 已有首作品 | script 三步流水线（`ScriptSteps`：确认镜头→准备资产→合成提示词） | 在现有作品上「再加 2 个镜头」 |
| 角色一致性 | 用户提「同一个人」 | `imageops` 三视图宫格（`VIEW_PRESETS`）+ `@` 引用 | 给已有角色补三视图 |
| 画质提升 | 用户觉得糊 | `enhance` 节点 | 把 S3 那条 480p 升到 1080p |
| 白模漫剧 | 用户提「漫剧/分镜稿」 | `previz` 节点（跳 `/project/:id/previz/:nodeId`） | 独立小项目 |
| 画布复用 | 用户建到第 3 个项目 | `groupSelectedNodes:681`、复制粘贴、工作流复用 | 在已有作品上演示 |

**解锁原则**：不弹窗、不弹教程；只在用户遇到对应场景时由 AI 提一句「这个我有个更快的做法，要试试吗」。

### 2.6 对话消息组件（需新写）

| 组件 | 用途 |
|---|---|
| `TextBubble` | 普通对话，支持打字机效果 |
| `StepCard` | 当前步骤卡（第 2/6 步 + 一句解释 + 进度点） |
| `ArtifactCard` | 产物卡：图片/视频缩略图 + 「看看 / 重做 / 换一个」 |
| `ProgressBubble` | 长任务进度（复用 SSE 的 `progressMessage`） |
| `ConfirmCard` | 花钱前确认（预计消耗 + 当前余额） |
| `SpotlightHint` | 指向真实 UI 的浮层提示 |
| `SuggestionChips` | 可点建议回复，替代选择题 |

外观一律用 `var(--dv-surface-2 / --dv-text-2 / --dv-border-1)` 与 `.tech-skeleton`，保证与暗色主题一致。

### 2.7 交互细则

- **可接管**：用户改了 AI 建的节点 → `data.managedBy='user'`，AI 之后只读。
- **可跳过**：每步右上角「我自己来」，跳过不打断流程。
- **可重入**：进度存后端，关页面/换设备接着做。
- **失败处理**：气泡内给「重试 / 换模型 / 跳过」，并说明积分已退回。
- **移动端**：对话栏变全屏抽屉；`spotlight` 退化为「已为你定位到画布」按钮。
- **顺带成为答疑入口**：老用户也能随时叫出来问「这个节点怎么用」。

### 3.2 为什么编排器放前端

1. 画布状态是前端 zustand 状态，后端要驱动就得把「加节点/连线/改参数」全 API 化——重复建设且极易不一致。
2. `spotlight` 高亮真实 UI 只能前端做。
3. 失败重试、用户接管、暂停继续，在前端状态机里最自然。
4. 后端保持薄，LLM 成本可控。

**代价**：进度需主动上报后端，否则换设备会丢 → 用 §3.3 的表解决。

### 3.3 数据模型

只加一张表（GORM AutoMigrate 自动建）：

```go
// OnboardingProgress 新手引导进度（一个用户一行）
type OnboardingProgress struct {

    Stage       int            `gorm:"not null;default:1"` // 1=首作品 2=进阶

    SkillData   datatypes.JSON `gorm:"type:jsonb"`         // 各步产物与用户选择（题材/风格/节点 id）
```

对话消息**不入库**（前端内存 + 可选 localStorage），只持久化「进度 + 关键产物」。

### 3.5 编排策略：**第一版用纯脚本状态机（A），后续可演进到 C**

| 档 | 做法 | 优点 | 缺点 | 决定 |
|---|---|---|---|---|
| **A. 纯脚本状态机** | 步骤与话术写死，LLM 只做内容生成 | 稳定、可控、成本最低 | 对话感弱 | ✅ **已确认，第一版就用它** |
| **B. 全 LLM function calling** | 模型自己决定调哪个工具 | 最自然 | 网关不支持 tools/stream，需大改；易乱调 | 不做 |
| **C. 混合（终态）** | 状态机决定「这步能做什么」，LLM 只负责**话术 + 参数抽取**，输出结构化 JSON 指令，前端白名单校验后执行 | 稳定与自然兼得 | 需设计指令协议 | 留到后续版本 |

```jsonc
// POST /api/onboarding/chat → 出参示意
{
  "reply": "好，我先把这个故事写出来，大概三四句话。",
  "commands": [
    { "skill": "generate_story", "args": { "prompt": "橘猫 雨天 窗台", "tone": "温暖" } }
  ],
  "next_step": "s2_image"
}
```

后端只产出 `commands`，**执行权在前端**（白名单 + 参数校验）；LLM 永远不能直接操作画布或扣费。

### 3.7 与执行引擎对接（**这里最容易踩坑**）

1. **执行是单节点的**：`workflowApi.execute(projectId, startNodeId)` 的 `startNodeId` 必填，全图执行已下线。编排器必须**自己按依赖顺序逐节点触发**（图 → 视频 → 旁白）。
2. **必须用 `utils/runNodes.ts:41 startNodeExecutions(projectId, nodeIds)`**，它已封装四步：存画布 → 本地置 `running` → 调 execute → `addActiveStream`。**漏掉第 4 步的后果**：节点永远停在「正在生成中」，没有进度也没有收口（`runNodes.ts` 注释里写明了）。
3. **补一道空输入自检**：`useNodeGeneration.ts:54 checkInputBeforeGenerate` 目前只在 hook 路径里，建议抽成导出供 skill 复用，避免助手造出「点了没反应」的空转。
4. **进度不用新建 SSE**：订阅已经常驻在 `WorkspacePage.tsx:225-227`，编排器直接读 `useExecutionStore` 的 `activeStreams` / `nodeErrors` 即可叙述进度。
5. **一个作品是多次执行**：图一次、视频一次、音频一次，编排器要串起来，不能假设「执行一次就完事」。
6. **失败与退费**：`failed` 时气泡给「重试 / 换模型 / 跳过」，并复用现有退费机制说明积分已退回。

### 3.8 提示词设计

- 角色设定（蛙导）、语气（搭档不是客服）、**禁用词**（「请点击」「第一步：」这类教程腔）。
- **一次只说一件事**，回复 ≤ 2 句；不解释原理，除非用户问。
- 只输出约定 JSON（`reply` / `commands` / `next_step`），复用 `cleanJSONMarkdown`（`script.go:196`）容错。
- 题材→故事直接复用 `GenerateStory`，不另写提示词。
- **节点知识源**：用 `plugins/registry.ts:60 list()` 生成「节点类型 / 能接什么上游 / 产出什么」，用 `:65 validateConnection()` 在用户手动乱连时给出纠错话术。

### 3.9 积分与成本方案（**已确认：阶段一平台承担，付费点在阶段二**）

**问题**：新用户 0 积分，`POST …/workflows/execute` 会被 `Billing` 中间件以 `402 / code 4002` 拒绝（中间件**只校验余额**，真正扣费在 `engine` 各执行器里按节点完成）。

**结论：阶段一的两笔生成（故事 15 + 首帧图 26）由平台承担，付费点后移到「图 → 视频」。**

两种实现方式，**推荐「引导免单」而不是「赠送积分」**：

| 方式 | 做法 | 评价 |
|---|---|---|
| **引导免单（推荐）** | 执行时带 `onboarding` 上下文，服务端判定「属于引导项目 且 未超出免单次数」则跳过扣费 | ✅ 额度**不可挪用**、不怕被薅成通用余额、账目可审计 |
| 赠送积分 | 注册/首次进引导时发 41+ 积分，写 `billing_records` | 实现简单，但积分可挪作他用，且有刷号风险 |

免单需要加三道闸：① **硬上限**：每用户仅前 2 次生成免单（1 次正文 + 1 次重试），且必须由引导编排器发起（带标记，不能由用户直接在画布上触发）；② **只在引导项目内**（校验 `project_id`）；③ 记录 `OnboardingProgress.CreditsUsed` 便于对账。

**成本**

| 项 | 积分 | 折算（试用包 60 积分/元 ~ 创作者包 100 积分/元） |
|---|---|---|
| 阶段一：故事 15 + 首帧图 26 | 41 | **≈ 0.4~0.7 元/人** |
| 阶段二：视频 480p（40~52）+ 旁白 26 | 40~78 | 用户自付 |
| 首作品总计 | 81~119 | — |

**首充礼包定价建议**：线上现有最低档是「试用包」50 元 / 3000 积分（`points_packages`，badge「学生试用」）。对一个刚聊了 3 分钟、还没看到成品的用户，**50 元门槛偏高**。建议做 **9.9~19.9 元的首充礼包（给 500~1000 积分）**，够完成首作品 + 若干次重试，兼顾转化率与「首充超值」感。

## 5. 风险与对策

| 风险 | 对策 |
|---|---|
| **积分成本失控** | 阶段一免单锁便宜档模型 + 硬上限 2 次；话术用 `flash` 级模型 |
| **付费点流失（本方案的枢纽风险）** | 支付**不跳出对话**、到账自动推进；拒绝后挂起而非中断，并设冷却期换话术复提 |
| 引导与真实 UI 脱节 | 一切走真实 `canvasStore` + 真实执行，不做假 demo |
| 用户想自己玩 | 随时「我自己来」；`managedBy:'user'` 的节点 AI 不再覆盖 |
| 生成失败（线上 11%） | 气泡内重试/换模型/跳过 + 明确退费 |
| 负面审核不过 | 给「换个说法」的引导，而不是抛 400 |
| 对话跑偏 / 乱调工具 | 执行权在前端白名单；LLM 只产出预定义 `commands` |
| 老用户被打扰 | 存量用户**不自动展开**，只保留常驻入口供主动提问（答疑用） |
| 执行卡住（漏订阅 SSE） | 强制走 `startNodeExecutions`，并在 code review 里盯 `addActiveStream` |

## 6. 度量

漏斗现在多了一个枢纽节点（付费），指标要按**三段**拆开看——否则数据不好时，分不清是引导没做好，还是用户就是不想付钱。

| 段 | 指标 | 说明 |
|---|---|---|
| **阶段一（免费）** | 阶段一完成率、拿到首帧图的中位时长 | 目标 ≥ 80%、≤ 3 分钟 |
| **付费衔接** | **付费转化率**、**付费后自动推进成功率** | 本方案最该盯的数字；后者直接反映 §2.4 做没做对 |
| **阶段二 → 首作品** | 首作品完成率（注册 24h 内发布首条）、完成时长中位数 | 北极星 |

**过程**：引导展开率、各步流失率（哪一步掉得最多）、平均对话轮数、跳过率、重试率、**拒绝付费后的复提转化率**。

**商业**：7 日留存、第二作品率、首充礼包转化率与客单价、单个激活用户成本（含阶段一免单的 ≈ 0.4~0.7 元）。

**反指标**：LLM 成本/人、阶段一免单被滥用次数、引导期间执行失败率、用户手动接管比例（过高说明 AI 做的不是用户想要的）。
