# 推荐码与邀请统计

每个用户有一个不可修改的推荐码。个人中心提供推荐码、邀请链接和直接邀请人数。
桌面个人中心采用左右布局，手机使用单列；“复制邀请链接”旁提供“我的邀请统计”按钮，
展示当前用户累计、近7天、近30天直接邀请注册人数和30天趋势。
个人统计通过当前登录身份隔离，不接受查询其他用户的ID。
同时展示直接邀请用户的累计付费人数、成功充值金额与笔数、充值到账积分、
人工充值/赠送积分、累计消费、已退积分和净消费；仅返回汇总，不返回个人支付或消费明细。
邀请链接带 `ref` 参数，注册表单自动带入，也可以手动输入。
推荐关系只在注册成功时建立，不回填旧用户、不允许注册后改绑，也不做多级分销或奖励。

后台新增“邀请统计”，支持搜索推荐人和查看其邀请用户明细；
用户管理也显示邀请者。相关统计接口仅管理员可访问。

统计采用当前有效账号的直接邀请关系，按全周期累计：

- 平台用户数：当前账号总数。
- 邀请注册用户数：当前仍存在的推荐人与其直接邀请用户。
- 付费用户数：邀请用户中至少有一个 `paid` 订单的用户数。
- 成功充值金额：只累计 `payment_orders.status = paid` 的金额，数据库以分保存。
- 付费充值积分：上述成功订单的积分；未支付和关闭订单不计。
- 人工充值/赠送积分：`billing_records.type = recharge` 且订单号为空的积分。
- 累计消费积分：账单 `deduct` 的合计。
- 已退积分：账单 `refund` 的合计。
- 净消费积分：累计消费减已退积分。

订单和账单分别按用户聚合，再关联邀请关系，避免多订单乘多账单造成重复统计。
不更改现有充值、扣费与退款流程。

历史用户首次打开个人中心时自动领取唯一推荐码；新用户注册时生成。
唯一索引允许历史空值，避免上线迁移时因旧账号均无推荐码而失败。

## 验证

- `go test ./internal/service -run TestReferral -v`：在随机独立 PostgreSQL schema 中验证注册绑定、
  旧账号推荐码、成功订单口径、账单退款和聚合不重复，结束后清理 schema。
- `go test ./internal/handler -run TestReferral`：管理员权限和非管理员作者选择器的数据隔离。
- `npm run test:referral`：链接填码、规范化、跨页面暂存及登录后的清理。
- `node tests/referral-browser.mjs`：拦截 API 验证后台明细、个人中心和邀请注册表单。
