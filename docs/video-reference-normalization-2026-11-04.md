# 视频参考素材对应关系规范（2026-11-04）

## 处理规则

- 图片、视频、音频分别从 1 编号；提示词的 `@` 标记转换为实际发送的“图1”、
  “视频1”、“音频1”，并附带对应节点名称与用途说明。
- 元数据先按提示词中的首次引用顺序校正，再按素材类型和节点去重。
  同一节点的不同引用标记仍指向同一个素材编号。
- 预演同时提供静帧和视频时，一个引用明确改写为“图N、视频N”。
- 风格图在普通参考图之后追加并声明仅参考风格；首尾帧模式不隐式加入风格图。
- 参考模式沿用各类素材各自的连线兜底规则；没有显式视频引用时只补第一个视频，
  与现有前端的参考视频时长预估一致。
- 首尾帧模式明确写出“首帧（图1）”、“尾帧（图2）”。同一张图可同时用于两帧。
  分镜节点有 `scriptNodeId`、`shotId`、`refIndex` 时，按声明的槽位定位，
  不会因为提示词先提到尾帧就交换两帧。
- 首尾帧模式不接受显式视频或音频引用；普通连线上的视频/音频不参与该模式。
- 显式引用缺失、连线兜底缺失、图片超过上限、首尾帧数量或槽位不明确时，
  在扣费前报错。不得通过静默截断或跳过素材来继续生成。
- 素材准备失败同样在扣费前报错。转换结果放在请求上下文中，
  原始视频 URL 仍用于时长测量、限制校验与计费，最终协议构造使用缓存转换结果。
- 上游任务续查直接复用原任务，不因当前画布引用失效而重新下发或扣费。

视频客户端的四条协议路径共用严格的素材收集器：

| 渠道 | 模型协议 | 提示词 | 素材 |
| --- | --- | --- | --- |
| 华数 | Seedance | `prompt` | `metadata.content` |
| 华数 | 万相 | `prompt` | `metadata.input.media` |
| 电信 | 火山 cdance | `content` 中的文本项 | `content` 中的媒体项 |
| 电信 | 万相 | `input.prompt` | `input.media` |

## 验证

回归测试包含四条协议各自的全能参考、首尾帧请求，共 8 条端到端请求检查。
所有请求发往本机模拟上游，不生成真实视频，不扣用户积分。

另外覆盖：

- 跨类型独立编号、重复别名、旧数组顺序、风格图、预演双素材。
- 首尾帧同图、声明槽位、只有尾帧、未完成首帧、模式冲突和数量超限。
- 素材转换失败时停止，缓存转换结果且不重复下载，原始地址不被改写。
- 旧节点未设置模式但有多张图片时，明确使用 `reference_image` 角色。

执行检查：

```sh
cd server
go test ./...
go test -race ./internal/engine ./internal/llm
```

这些检查验证素材编号、角色与实际请求内容的一致性，不保证模型最终完全遵循每条创作指令。
